# AI4S Literature Workbench v0.1.0 Release Plan

> Status: release candidate preparation. The v0.1.0 scope is locked to the
> evidence-to-Zotero workflow and verified public-OA fulltext handoff. The Web
> of Science (WoS) browser backend is deferred to a later version because it
> has not completed live acceptance.

## Release promise

v0.1.0 is an auditable literature-workflow plugin for **macOS and native
Windows**. It supports evidence retrieval/ranking and writing, controlled
Zotero operations, EasyScholar metrics for new imports, and OA-first verified
PDF handoffs. WSL is a compatibility target, not a release gate.

## In scope

- `literature-research`, `literature-manager`, and `literature-writing` bundle
  and their documented handoffs.
- Zotero reviewed imports, project collection/report sync, metrics, Priority,
  Agent Tags, and explicitly requested AI Summary.
- OA HTTP/PMC and reviewed public PDF candidates, verified before a separate
  controlled Zotero attachment write.
- Native macOS and Windows bootstrap, marketplace installation, and documented
  privacy/credential boundaries.

## Explicitly deferred

- Web of Science browser MCP: Core Collection live search, filtering,
  result-count verification, and official export. Existing users may still
  import a manually obtained official WoS export with `import-wos-export`.
- Crossref and all other commercial database adapters.
- VPN/WebVPN automation, credential or Cookie handling, CAPTCHA bypass, or
  hidden-browser operation.
- Institutional/SSO full-text fallback. v0.1.0 supports public OA routes only.
- Automatic Zotero duplicate merges/deletions and automatic modification of
  user Priority.

## Release gates

1. **Local regression:** run all runtime, skill, and add-on tests; build each
   shipped runtime; run bundle sync/check and MCP smoke verification.
2. **Platform and Zotero acceptance:** the macOS and Windows native
   clean-install/onboarding acceptances are complete.
3. **Fulltext live acceptance:** confirm one known OA item completes
   `fulltext_fetch_submit` → verified handoff →
   `zotero_apply_fulltext_handoff`, with exactly one child PDF attachment.
   Record only compact counts and actionable failure codes; never retain the
   item key, PDF path, URL, or Zotero content.
4. **Release hygiene:** regenerate/check the bundle manifest, publish release
   notes with this support matrix and the deferred features, then tag the
   reviewed commit as `v0.1.0`.

## Release checklist

1. Update `README.md` and `CHANGELOG.md` so they do not advertise the deferred
   WoS backend or an unregistered database-browser MCP.
2. Complete the known-OA Fulltext live handoff and attachment check.
3. Run the local regression gate against the candidate commit.
4. Commit the final documentation, then create and push the `v0.1.0` tag.
