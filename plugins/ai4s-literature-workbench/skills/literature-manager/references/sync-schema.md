# Zotero Sync Schema

Use this reference when reading or writing Zotero match and sync JSON artifacts.

## Match Report

`match-evidence` writes:

```json
{
  "min_score": 0.8,
  "counts": {
    "evidence": 10,
    "zotero_items": 200,
    "matched": 8,
    "unmatched": 2
  },
  "matches": [],
  "unmatched": []
}
```

Each `matches[]` entry contains:

- `evidence_index`: index in the input ranked evidence.
- `evidence_id`: DOI, PMID, title, or source ID.
- `evidence_title`: normalized title field for inspection.
- `evidence`: original evidence record.
- `match`: Zotero match details, including `score`, `reasons`, `zotero_key`,
  `zotero_item`, and normalized identities.
- `status`: `matched`.

Each `unmatched[]` entry preserves the original evidence and any weak candidate
so the agent can decide whether to import, ignore, or manually search Zotero.

## Sync Plan

`plan-sync` writes:

```json
{
  "project": "project-name",
  "search_date": "2026-07-10",
  "collection_name": "Project Collection",
  "collection_key": "ABCD1234",
  "unmatched_policy": "check-before-import",
  "actions": [],
  "unmatched": []
}
```

Each `actions[]` entry contains:

- `action`: currently `update-existing-item`.
- `zotero_key`: target Zotero item key.
- `add_to_collection_key`: collection key, or null if unresolved.
- `collection_name`: human-readable collection name.
- `add_tags`: project, search-date, domain, evidence-level, and normalized
  per-record Article Type tags.
- `note`: proposed evidence note content for review.

## Tag Conventions

Use stable machine-readable tags:

- `project:<short-name>`
- `search-date:YYYY-MM-DD`
- `domain:<disease-or-field>`
- `method:<assay-or-model>`
- `evidence-level:high|moderate|screen|unspecified`
- `AI4S:ArticleType:Article|Review|Systematic Review|Clinical Trial|...`

Article Type tags come from structured source-database metadata. Do not infer
them from titles or abstracts during Zotero sync. The namespace makes them
editable/filterable in Zotero while allowing the desktop add-on to render the
values without the prefix.

Avoid storing private project secrets, unpublished results, PDF paths, API keys,
or local filesystem paths in Zotero tags or notes generated by this workflow.

## Duplicate Report

`dedupe-library` writes duplicate clusters without modifying Zotero:

```json
{
  "count": 1,
  "min_title_score": 0.92,
  "clusters": [
    {
      "cluster_id": 1,
      "items": []
    }
  ],
  "policy": "review-before-merge"
}
```

Review duplicate clusters manually in Zotero before merging. DOI/PMID duplicates
are usually strong candidates; title-year duplicates require checking authors,
journal, and publication type.
